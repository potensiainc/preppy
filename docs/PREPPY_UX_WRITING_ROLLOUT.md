# PREPPY UX Writing 적용 기록

기준: [PREPPY UX Writing Policy](PREPPY_UX_WRITING_POLICY.md) v1.0

## 적용 범위

이번 변경은 기존 제품의 표시 문구에 적용했어요. 새로운 기능이나 수집·저장 구조를 만들지 않았어요.

| 영역 | 바꾼 내용 |
| --- | --- |
| 홈·탐색·공통 화면 | 짧은 한국어 제목, 구체적인 행동명, 과장하지 않는 서비스 소개 |
| 기관·모집·입학 안내 | 해요체, 조건별 목록, 세미콜론 구분 정리, 공식 출처와 확인 시점 안내 |
| 로그인·관심기관 | 실제 동작에 맞는 ‘관심기관 등록’, 로그인 확인 실패와 비로그인 구분, 실패 후 재확인 경로 |
| 내 프레피·기본 설정 | 필수·선택 구분, 저장 이후 반영 안내, 알림 준비 상태에 맞는 설명 |
| 아티클·SEO | 본문·요약·검색 설명의 말투 통일, 검증 범위를 넘는 홍보 표현 제거 |
| 관리자 | 메뉴·필드·확인·오류·복구 안내를 한국어로 정리하고 정확한 작업 범위 유지 |
| 이메일 | 시스템 제목과 링크 행동명 정리. 공식 제목·동적 원문 요약은 보존 |

## 중요한 표현 기준

- `제출해야 한다` → `제출해야 해요`: 의무를 권장으로 바꾸지 않아요.
- `입학이 취소될 수 있다` → `입학이 취소될 수 있어요`: 가능성을 확정 사실로 바꾸지 않아요.
- `업데이트 받기` → `관심기관 등록`: 관심기관 저장만으로 이메일 발송을 약속하지 않아요.
- `Last Collected` / `Last Verified` → `자료 수집` / `내용 확인`: 원래 두 timestamp 값은 그대로 유지해요.
- `UNKNOWN`은 `미확인`으로 안내해요. 실제 진행 여부를 모르는 상태를 ‘확인 중’이라고 표현하지 않아요.
- 로그인·저장 결과를 확인하지 못했으면 실패 원인이나 DB 상태를 추측하지 않고 재확인 방법을 안내해요.

## 원문·사실 보존

변환은 표시 계층에서만 수행해요. canonical 데이터, 공식 evidence, 수집 결과, 검수·공개 상태는 변경하지 않았어요.

- 학년도, 날짜, 시간, 금액, 인원, URL, 이메일 주소를 보존해요.
- 원본 서류 조건, 제출·납부 기한, 지원 제외, 개인정보 동의 거부, 불참·중복등록 시 취소 조건을 보존해요.
- 과거 학년도 수업료와 변동 가능성, 원문 날짜의 불일치와 학교 확인 필요 문구를 보존해요.
- 공식 인용문은 말투를 바꾸지 않아요. 아티클에서 인용이 인라인 서식을 가로지르면 해당 문단 전체를 보수적으로 보존해요.
- HTML 속성·링크·인용 블록·코드·공식 제목은 변환 대상에서 제외해요. 기존 HTML 정화 경계를 유지해요.
- 내부 enum, 운영 진단 코드, 정확한 API 계약은 유지해요. 공식 원문과 기계용 문자열까지 일괄 치환하지 않아요.

### 실제 데이터와 화면

- 기존 실제 공개 DTO 스냅샷의 41개 기관·69개 입학 안내를 현재 React 컴포넌트로 다시 렌더링했어요.
- 69개 저장 모집요강에서 기존 출처 해설 정리 이후 남는 숫자·URL·이메일 토큰 보존 회귀가 통과했어요.
- 41개 기관 HTML의 설명 문장에서 점검 대상인 `한다/된다/이다/있다/없다/합니다/됩니다` 종결문 잔여가 0건인 것을 확인했어요. 모든 한국어 표현을 판별하는 일반 언어 검사라는 뜻은 아니에요.
- Chromium에서 동광·리라·금성·중앙기독의 실제 안내와 공식 출처, 필수 조건, 교육비 연도, 두 확인 시점을 확인했어요.
- 390px 모바일에서 여러 일정과 로그인·관심기관 오류 안내를 확인했어요. 긴 로그인 오류 문구가 잘리지 않도록 줄바꿈을 보완했어요.
- 기본 설정의 필수·선택 동의, 운영 화면의 한국어 안내와 복구 행동을 실제 컴포넌트로 확인했어요.
- 브라우저 검수는 로컬 SSR 스냅샷과 명시적인 합성 상태를 사용했어요. Production 브라우저·OAuth 로그인·실제 이메일 발송의 E2E 검증으로 주장하지 않아요.

### 검토 반영

독립 코드 검토에서 발견한 인라인 서식 사이 공식 인용문 변환 문제를 수정하고 회귀를 추가했어요. 재검토에서 남은 Critical/Important 문제는 없었어요.

## 변경하지 않은 것

- Production DB, 데이터 수집·추출·검수·공개 처리
- 스키마, migration, package dependency
- 외부 이메일·알림 발송
- 기존 미추적 리서치·벤치마크·통학·목업 자료
- Git commit / push / Production deploy

검증용 PostgreSQL은 localhost 전용 disposable 환경을 사용했어요. 초기 백업 테스트의 Compose 서비스 불일치와 읽기 전용 테스트의 DB명·사전 schema 요구를 맞춘 뒤 전체 회귀가 통과했어요. 검증용 DB/container와 전용 Docker network는 검증 후 정리했어요.

**UX Writing: PASS** — 기존 사용자 접점의 문구에 정책을 적용했고, 사실·조건 보존 회귀와 로컬 화면 검수를 통과했어요. 공식 원문 인용과 기계용 문자열은 의도적으로 유지해요. 이 판정은 Production 배포 완료를 뜻하지 않아요.
