# PREPPY 교육시장 브리핑 하이브리드 편집 파이프라인 설계

- 상태: Owner 방향 승인 · 서면 설계 검토 대기
- 승인한 방향: 하이브리드 편집 파이프라인
- 작성일: 2026-09-13
- 기준 시간대: Asia/Seoul
- 적용 정책: [PREPPY UX Writing 정책](../../PREPPY_UX_WRITING_POLICY.md)

## 1. 목적

매주 월요일 오전 8시에 실행되는 ChatGPT 예약 작업 `정기 교육시장 브리핑`의 결과를 PREPPY의 콘텐츠 후보로 사용한다. 예약 작업의 문장을 그대로 공개하지 않고, 부모의 의사결정에 도움이 되는 항목만 선별해 공식 근거와 PREPPY의 현재 데이터에 대조한 뒤 아티클 초안을 만든다. 최종 발행은 운영자가 승인한다.

이 파이프라인의 목표는 다음 세 가지다.

1. 입학 일정, 비용, 정책, 프로그램 변화를 빠르게 발견한다.
2. 확인된 사실과 확인하지 못한 내용을 분리한다.
3. 아티클을 관련 기관·입학정보·관심 등록으로 연결한다.

## 2. 배경과 확인한 실제 사례

2026-09-12 기준 첫 브리핑에는 다음 항목이 포함됐다.

- 취학 전 유아 대상 평가 제도 변화
- 영훈초 2027학년도 입학설명회 신청
- KIS 판교 오픈하우스
- 종료된 Dwight Seoul 오픈하우스
- 연도 표기가 충돌하는 ACA 서초 설명회 일정
- 공식 확인이 끝나지 않은 서울 사립초 공통 일정

한 번의 브리핑 안에도 즉시 기사 후보, 추가 검증 후보, 데이터만 수정할 항목, 공개하지 않을 항목이 함께 있었다. 따라서 예약 작업 결과를 아티클로 직접 변환하거나 자동 발행하는 구조는 사용하지 않는다.

ChatGPT 예약 작업은 정기 실행, 결과 확인, 알림과 관리 기능을 제공한다. 그러나 PREPPY 프로덕션이 개인 ChatGPT 대화 결과를 직접 소비하는 전용 반입 경로는 이 설계의 전제로 삼지 않는다. 공식 문서에 확인되지 않은 비공개 대화 API, 화면 스크래핑 또는 고정 대화 ID 의존성을 만들지 않는다. 반입 방식은 교체 가능한 어댑터로 격리한다.

## 3. 핵심 결정

### 3.1 예약 작업 결과는 후보이지 사실 원본이 아니다

브리핑은 변화 탐지와 편집 아이디어의 입력이다. Institution, Opportunity, 비용, 일정, 자격의 사실 원본은 기존 PREPPY 검증 데이터와 Evidence다.

금지 흐름:

```text
브리핑 문장
→ 검증 없이 아티클 공개
→ 아티클을 근거로 기관·입학정보 DB 수정
```

허용 흐름:

```text
브리핑 문장
→ 콘텐츠 후보
→ 출처 수집·사실 검증
→ Institution/Opportunity의 검증된 현재값 반영
→ 아티클 초안
→ 운영자 승인
→ 공개
```

### 3.2 자동화 경계

자동으로 수행할 수 있는 일:

- 브리핑 반입과 원문 보관
- 후보 분리와 중복 탐지
- 카테고리·유형·우선순위 제안
- 출처 URL 추출과 공식 도메인 후보 표시
- 기존 기관·입학정보 관계 제안
- 발행 조건을 충족한 후보의 초안 생성
- 마감 또는 재검수 필요 후보를 운영 큐에 표시

사람 승인이 필요한 일:

- 상충하는 날짜·학년도·자격의 최종 판단
- 비공식 원비·후기·댓글의 공개 범위 결정
- 법령 또는 정책 해석 승인
- 아티클의 공개 승인
- 정정, 발행 취소, 아카이브 결정

완전 자동 발행은 이번 설계 범위에 포함하지 않는다.

### 3.3 아티클은 제품 탐색으로 연결한다

아티클은 독립 뉴스 게시판이 아니다. 관련된 공개 Institution과 Opportunity가 있으면 구조적 관계로 연결한다. 공개되지 않은 관계 대상은 사용자 CTA로 노출하지 않는다.

## 4. 범위

### 포함

- 영어유치원, 사립초, 국제학교 교육시장 브리핑 반입
- 콘텐츠 후보 선별, 검증, 초안, 검수, 승인, 발행
- 기존 Article CMS의 `GUIDE`, `UPDATE`, `ROUNDUP` 사용
- 기존 Article 상태 `DRAFT`, `PUBLISHED`, `UNPUBLISHED`, `ARCHIVED` 사용
- 관련 Institution 및 Opportunity 연결
- 근거·검수·브리핑 실행 이력의 추적
- 발행 후 기한 경과·출처 변경 재검수

### 제외

- 자동 기사 발행
- 기사 내용을 근거로 검증 데이터 자동 수정
- 비공식 댓글의 사용자 개인 식별 정보 보관
- 유료 커뮤니티 접근 우회 또는 약관을 위반하는 수집
- 댓글 수나 게시 빈도를 만족도 점수로 단순 환산
- 별도 뉴스레터 제품 구축
- 전체 크롤러 및 범용 검색 엔진 구축

## 5. 부모 관점의 콘텐츠 선정 기준

후보는 다음 질문에 답할 때만 아티클로 발전시킨다.

1. 우리 아이에게 해당하는 변화인가요?
2. 언제까지 무엇을 해야 하나요?
3. 비용·자격·일정·통학·교육과정 판단에 영향을 주나요?
4. 공식 안내에서 어디까지 확인됐나요?
5. PREPPY에서 다음에 확인할 기관이나 입학정보가 있나요?

내부 점수는 다음 여섯 항목을 각각 0~2점으로 계산한다.

| 항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 부모 영향 | 참고 수준 | 일부 가정 영향 | 지원·비용·선택에 직접 영향 |
| 시급성 | 기한 없음 | 30일 이내 | 14일 이내 또는 시행 임박 |
| 근거 강도 | 출처 불명 | 보도·기관 인용 | 정부·교육청·기관 공식 원문 |
| 검색 의도 | 불명확 | 기관명 탐색 | 명확한 일정·비용·제도 질문 |
| 제품 연결 | 연결 대상 없음 | 기관 또는 일정 한쪽 | 기관과 현재 입학정보 모두 |
| 지속 가치 | 일회성 기록 | 단기 검색 가치 | 다음 모집에도 쓰이는 기준 |

처리 기준:

- 10~12점: P0, 공식 재확인 후 당일 초안
- 7~9점: P1, 2영업일 내 검증·초안
- 4~6점: P2, 상시형 콘텐츠 백로그 또는 DB 갱신만 수행
- 0~3점: 공개 콘텐츠에서 제외
- 날짜·학년도·금액·자격에 해결되지 않은 충돌이 있으면 점수와 무관하게 발행 보류

## 6. 콘텐츠 유형과 카테고리

### 유형

- `GUIDE`: 여러 모집 주기에도 유효한 설명·비교 기준
- `UPDATE`: 확인된 특정 변경이나 일정
- `ROUNDUP`: 같은 판단 목적을 가진 여러 기관 또는 입학정보 정리

### 공개 카테고리

| DB 분류 | 목록 경로 | 사용 예 |
|---|---|---|
| `ENGLISH_KINDERGARTEN` | `/article/영유` | 영유 정책, 비용, 모집, 선택 기준 |
| `PRIVATE_ELEMENTARY` | `/article/사립초` | 사립초 모집, 설명회, 통학, 교육과정 |
| `INTERNATIONAL_SCHOOL` | `/article/국제학교` | 국제학교 입학자격, 오픈하우스, 교육과정 |
| `ADMISSIONS_GENERAL` | `/article` | 둘 이상의 분류에 공통인 입학 준비 |

상세 canonical 경로는 기존 `/articles/{slug}`를 유지한다.

### 발행하지 않는 경우

- 종료 상태 변경만 필요한 행사
- 확인된 변화가 없는 주간 브리핑
- 공식 근거 없이 반복되는 홍보성 발표
- 동일 기관·동일 일정의 기존 아티클과 실질적으로 중복되는 항목
- 날짜·학년도·금액·자격 충돌이 해결되지 않은 항목

ROUNDUP은 공개 가능한 검증 항목이 세 건 이상이고 하나의 부모 질문으로 묶일 때만 만든다. 발행량을 채우기 위한 주간 요약은 만들지 않는다.

## 7. 논리 데이터 모델

기존 `articles`, `article_institutions`, `article_opportunities`는 유지한다. 다음 편집 추적 단위를 추가한다.

### `briefing_runs`

- `id`
- `source_kind`: `CHATGPT_SCHEDULED_TASK`
- `source_task_label`: `정기 교육시장 브리핑`
- `source_run_at`
- `source_timezone`
- `imported_at`
- `raw_body`
- `raw_sha256`
- `status`: `IMPORTED`, `PARSED`, `PARTIAL`, `FAILED`
- `failure_code`, `failure_summary`

원문은 수정하지 않는다. 같은 해시와 실행 시각의 중복 반입은 한 번만 허용한다.

### `editorial_candidates`

- `id`, `briefing_run_id`
- `status`
- `priority`: `P0`, `P1`, `P2`
- `article_type`, `article_category`
- `working_title`, `parent_question`
- `summary`
- `publish_by`
- `decision_reason`
- `confidence`
- `duplicate_of_candidate_id`
- `draft_article_id`
- `created_at`, `updated_at`

후보 상태:

```text
NEW
NEEDS_VERIFICATION
READY_FOR_DRAFT
DRAFTED
REVIEW_REQUIRED
APPROVED
PUBLISHED
REJECTED
EXPIRED
```

정상 전이:

```text
NEW
→ NEEDS_VERIFICATION
→ READY_FOR_DRAFT
→ DRAFTED
→ REVIEW_REQUIRED
→ APPROVED
→ PUBLISHED
```

근거 충돌은 `NEEDS_VERIFICATION`으로 되돌린다. 발행 전에 행동 기한이 지나고 역사적 가치가 없으면 `EXPIRED`로 전환한다. `REJECTED`와 `EXPIRED` 기록은 삭제하지 않는다.

### `candidate_sources`

- `candidate_id`
- `source_url`, `canonical_url`, `source_title`
- `source_tier`
- `claim_scope`
- `published_at`, `collected_at`, `verified_at`
- `status`: `FOUND`, `ACCESS_FAILED`, `CONFLICTING`, `VERIFIED`, `SUPERSEDED`
- 기존 Evidence와 연결 가능한 `evidence_id`

### `editorial_reviews`

- `candidate_id`, 선택적 `article_id`
- `review_type`: `FACT`, `UX_WRITING`, `SEO`, `LINK`, `FINAL`
- `outcome`: `PASS`, `FIX_REQUIRED`
- `reviewer_admin_id`
- `reviewed_at`
- `notes`

### `article_source_links`

- `article_id`
- `candidate_source_id`
- `relation_type`: `PRIMARY`, `SUPPORTING`, `CONTEXT`
- `claim_scope`
- `created_at`

아티클 본문에서 링크가 삭제되더라도 내부 근거 관계는 유지한다. 사용자에게 보여주는 공식 링크와 내부 Evidence는 목적을 구분한다.

## 8. 브리핑 반입 계약

### Phase 1: 운영자 반입

4주 파일럿 동안 운영자 또는 Codex가 최신 예약 작업 결과를 읽어 원문과 실행 시점을 반입한다. 대화 화면을 스크래핑하지 않고, 앱이 제공하는 읽기 기능 또는 운영자가 전달한 원문만 사용한다.

### Phase 2: 구조화된 결과

예약 작업의 사람용 브리핑 아래에 구조화된 후보 블록을 함께 생성하도록 프롬프트를 개선한다. 필수 필드는 다음과 같다.

```json
{
  "briefing_date": "YYYY-MM-DD",
  "timezone": "Asia/Seoul",
  "candidates": [
    {
      "working_title": "string",
      "parent_question": "string",
      "category": "ENGLISH_KINDERGARTEN | PRIVATE_ELEMENTARY | INTERNATIONAL_SCHOOL | ADMISSIONS_GENERAL",
      "suggested_type": "GUIDE | UPDATE | ROUNDUP",
      "priority": "P0 | P1 | P2",
      "affected_institutions": ["string"],
      "dates_and_amounts": ["string"],
      "source_urls": ["https://..."],
      "uncertainties": ["string"],
      "recommended_action": "DRAFT | VERIFY | DATA_ONLY | HOLD | IGNORE"
    }
  ]
}
```

구조화 블록이 없거나 일부가 손상되어도 사람용 원문은 보존하고 `PARTIAL`로 반입한다. 파싱 실패를 변화 없음으로 처리하지 않는다.

### Phase 3: 서버 소유 반입 경로

반복 운영이 안정되면 공식적으로 지원되는 연결 앱 또는 PREPPY가 소유한 입력 채널을 통해 구조화 결과를 전달할 수 있다. 연결 채널이 바뀌어도 `briefing_runs` 이후의 편집 파이프라인은 변경하지 않는다. 승인 대기 때문에 작업이 멈추는 외부 쓰기 동작은 무인 핵심 경로로 사용하지 않는다.

## 9. 출처와 검증 정책

출처 우선순위:

1. 법령, 정부, 교육청, 공식 입학포털
2. 학교·기관 공식 안내 및 공식 신청 페이지
3. 기관이 직접 제공한 보도자료나 공식 SNS
4. 신뢰할 수 있는 언론 보도
5. 블로그, 카페, SNS 게시물과 댓글

적용 규칙:

- 일정·학년도·지원 자격·법적 의무는 1~2단계 출처 없이 확정하지 않는다.
- 기관 보도자료는 기관 주장으로 귀속하고 독립 검증으로 표현하지 않는다.
- 블로그·카페·SNS·댓글은 부모 질문, 현장 신호, 추가 조사 대상을 찾는 데 사용한다.
- 비공식 원비는 기준 연도, 납부 단위, 포함·별도 비용, 확인 시점과 공식 미확인 상태를 함께 기록한다.
- 댓글 작성자의 이름, 계정, 자녀 정보, 연락처는 저장하거나 공개하지 않는다.
- 단일 익명 댓글을 현재 원비, 통학 노선, 식단, 입학 자격의 확정 근거로 사용하지 않는다.
- 출처 접근 실패는 정보 없음이나 미발표로 바꾸지 않는다.
- 출처가 충돌하면 두 값을 보존하고 발행을 보류한다.

## 10. 편집 워크플로우

### 10.1 월요일 브리핑 처리

1. 오전 8시 브리핑 실행
2. 실행 원문과 시점을 반입
3. 후보 단위로 분해하고 중복 검사
4. P0/P1/P2 및 `DRAFT/VERIFY/DATA_ONLY/HOLD/IGNORE` 제안
5. 운영자가 후보 판단을 확인

### 10.2 사실 검증과 제품 데이터 반영

1. 출처 페이지를 새로 열어 현재 상태 확인
2. 날짜, 요일, 시간대, 학년도, 비용 단위 대조
3. 관련 Institution/Opportunity 식별
4. 기존 값과 차이가 있으면 기존 검증 명령으로 현재값 갱신
5. Evidence와 확인 시점 기록
6. 공개 가능 상태가 아니면 내부 관계만 유지하고 사용자 CTA는 만들지 않음

### 10.3 초안 생성

`READY_FOR_DRAFT` 후보만 초안을 만든다. 생성 시:

- 기존 CMS로 `DRAFT` Article 생성
- 카테고리와 유형 지정
- 관련 Institution/Opportunity 제안
- 검색 제목과 설명 생성
- 공식 출처와 확인 시점 포함
- 이미지가 없어도 사실 전달과 발행 검수는 가능하게 유지
- 초안은 `robotsIndex=false`

### 10.4 검수와 승인

발행 전 필수 검수:

- `FACT`: 근거·날짜·비용·학년도·자격
- `UX_WRITING`: 정보 순서·불확실성·다음 행동
- `SEO`: 검색 제목·설명·canonical·중복 의도
- `LINK`: 공식 링크·관련 기관·관련 일정
- `FINAL`: 모바일 미리보기와 발행 승인

한 항목이라도 `FIX_REQUIRED`면 `APPROVED`로 전환하지 않는다.

### 10.5 발행 후

- Article을 관련 Institution/Opportunity와 연결
- 목록 카테고리에 노출
- 기한 경과 또는 연결된 Opportunity 상태 변경 시 재검수 큐 생성
- Opportunity 변경만으로 Article `dateModified`를 자동 변경하지 않음
- 신청이 마감되면 활성 신청 CTA를 제거하고 `설명회 신청 마감` 또는 `지난 일정`을 실제 상태에 맞게 표시
- 내용이 더 이상 부모 판단에 도움이 되지 않으면 `UNPUBLISHED` 또는 `ARCHIVED`를 운영자가 선택

## 11. 아티클 정보 구조와 문구

기본 순서:

1. 핵심 변화
2. 적용 대상
3. 중요한 일정
4. 지금 확인할 일
5. 비용·자격·프로그램·통학 등 판단 정보
6. 확인되지 않은 내용
7. 관련 기관과 입학정보
8. 공식 안내
9. 자료 수집 시점과 내용 확인 시점

사용자 문구 예:

- 공식 확인 완료: `학교 공식 안내에서 일정을 확인했어요.`
- 예정 상태: `예정된 일정이에요. 변경될 수 있어요.`
- 출처 접근 실패: `학교 페이지를 불러오지 못해 이번 변경을 확인하지 못했어요.`
- 날짜 충돌: `안내에 적힌 날짜가 서로 달라요. 정확한 일정은 학교에 확인해 주세요.`
- 외부 신청 이동: `학교 신청 페이지로 이동`

피할 문구:

- `놓치면 늦어요`
- `반드시 합격하는 방법`
- `학교 인증 정보`
- 공식 근거가 없는 `확정`, `최신`, `평균 원비`

## 12. 관리자 경험

기존 Article CMS에 별도 `브리핑 후보` 작업함을 연결한다.

목록에서 바로 확인할 내용:

- 부모 질문과 작업 제목
- P0/P1/P2
- 카테고리와 아티클 유형
- 공식 출처 확보 상태
- 날짜·금액 충돌 여부
- 관련 기관·입학정보
- 발행 권장 기한
- 다음 행동: `출처 확인`, `데이터 반영`, `초안 만들기`, `보류`, `제외`

상세 화면에서는 브리핑 원문, 후보 주장, 출처, PREPPY 현재값, 초안 문장을 나란히 비교할 수 있어야 한다. 모바일에서는 날짜·금액·충돌·다음 행동을 먼저 보여주고 원문은 접어서 제공한다.

## 13. 실패와 예외 처리

- 예약 작업 미실행: 기존 후보를 변화 없음으로 재사용하지 않고 `이번 브리핑을 가져오지 못했어요.`로 운영자에게 표시
- 중복 실행: 실행 시각과 원문 해시로 중복 방지
- 구조화 블록 오류: 원문을 보존하고 수동 분류 가능하게 함
- 공식 페이지 접근 실패: `ACCESS_FAILED`, 공개 보류
- 출처 충돌: `CONFLICTING`, 두 값을 모두 보존
- 초안 생성 실패: 후보는 `READY_FOR_DRAFT`에 남기고 재시도 가능
- 관계 대상 비공개: 아티클 내부 관계는 저장할 수 있으나 공개 CTA는 숨김
- 발행 시점에 기한 경과: `EXPIRED` 또는 역사적 가치를 검토한 뒤 제목·상태 갱신
- 운영자 동시 수정: 기존 CMS의 stale `409` 흐름을 유지

## 14. 보안과 개인정보

- 브리핑 원문에 포함된 비밀, 계정 정보, 개인 식별 정보는 Article에 전달하지 않는다.
- 커뮤니티 댓글은 필요한 주장만 비식별 요약하고 원문 계정 정보를 저장하지 않는다.
- 관리자 권한과 기존 Article 발행 권한을 우회하지 않는다.
- HTML은 기존 서버 sanitizer를 거친다.
- 예약 작업 공유 링크나 개인 대화 ID를 공개 근거 URL로 사용하지 않는다.
- 외부 앱의 쓰기 작업에 승인이 필요하면 무인 발행 경로를 중단하고 운영자에게 알린다.

## 15. 첫 브리핑 적용 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 영유 평가 제도 변화 | 법령 재검증 후 P0 `UPDATE`, 이후 `GUIDE` | 시장 전체 영향이 크지만 시행일·적용 범위의 법령 원문 대조 필요 |
| KIS 판교 오픈하우스 | 공식 페이지 재확인 후 P0 `UPDATE` | 일정이 임박하고 부모 행동이 명확함 |
| 영훈초 설명회 | 신청 양식의 회차·대상·마감 확인 후 P0/P1 `UPDATE` | 공식 홈페이지 신호는 있으나 세부 조건 미확인 |
| Dwight Seoul 종료 행사 | Article 없음, Opportunity 종료 검수 | 새 행동보다 상태 정확성이 우선 |
| ACA 서초 일정 | `NEEDS_VERIFICATION` | 보도된 연도와 모집 맥락 충돌 |
| 서울 사립초 공통 일정 | `NEEDS_VERIFICATION` | 공식 입학포털·교육청 확인 전 잠정 정보 |
| 변화 없음 항목 | Article 없음 | 얇은 주간 기사 방지 |

## 16. 단계별 출시

### Phase 1 — 4주 파일럿

- 매주 브리핑 원문 수동 반입
- 후보와 출처 구조화
- 운영자 검증
- 승인된 후보만 기존 CMS 초안 생성
- 사람만 발행

완료 조건:

- 네 번의 브리핑을 중복 없이 반입
- 모든 공개 Article이 후보와 근거로 역추적 가능
- 해결되지 않은 충돌이 있는 후보의 공개 0건
- 마감·종료 상태를 잘못 안내한 공개 0건

### Phase 2 — 후보·초안 자동화

- 구조화된 브리핑 결과 반입
- 후보 점수화와 중복 제안 자동화
- `READY_FOR_DRAFT` 초안 생성 자동화
- 검수·발행은 사람 승인 유지

### Phase 3 — 안정화

- 허용된 공식 출처의 재검수 큐 자동 생성
- 관련 Institution/Opportunity 제안 고도화
- 발행 후 성과와 정정 데이터를 후보 점수에 반영

완전 자동 발행 전환은 별도 Owner 결정과 별도 설계로만 진행한다.

## 17. 측정

핵심 운영 지표:

- 브리핑 후보 채택률
- P0 발견부터 공개까지 걸린 시간
- 출처 충돌·접근 실패·중복으로 보류된 비율
- 발행 후 정정률
- 기한이 지난 활성 CTA 노출 건수

핵심 사용자 지표:

- `article_view`
- `article_to_institution`
- `article_to_opportunity`
- `article_to_follow`
- 공식 신청 페이지 이동
- 검색 유입 후 관련 기관 탐색률

페이지 조회수만으로 성공을 판단하지 않는다. Article이 부모의 다음 확인 행동과 PREPPY의 기관 모니터링으로 이어지는지를 우선한다.

## 18. 검증 계획

### 단위 검증

- 브리핑 중복 반입
- 후보 상태 전이
- 점수 경계와 충돌 우선 보류
- 카테고리·유형 매핑
- 구조화 블록 부분 실패
- 비공개 관계 CTA 제외

### 통합 검증

- 브리핑 → 후보 → Evidence → DB 현재값 → Article Draft 관계
- 검수 실패 시 발행 차단
- 발행 Audit과 cache revalidation
- 마감·종료 변경의 재검수 큐 생성
- 같은 후보의 재실행과 멱등성

### 브라우저 검증

- 관리자 후보 목록과 상세 비교
- 초안 미리보기
- 데스크탑·태블릿·모바일 Article
- 긴 기관명, 여러 날짜, 긴 비용 조건 줄바꿈
- 외부 공식 링크와 실제 이동
- `설명회 신청 마감`, `지난 일정`, `확인 필요` 상태

## 19. UX Writing 검토

영향 채널:

- 공개 Article 제목·요약·본문·CTA
- `/article`, `/article/영유`, `/article/사립초`, `/article/국제학교`
- 관리자 후보·검수·오류 상태
- 검색 제목과 설명

보존 조건:

- 학년도와 실제 날짜를 분리한다.
- 비용은 기준 연도, 납부 단위, 포함·별도 항목과 함께 표시한다.
- 미발표, 미발견, 접근 실패, 예정, 상충, 마감을 구분한다.
- 공식 출처와 자료 수집·내용 확인 시점을 추적한다.
- 외부 이동 버튼은 실제 다음 행동을 설명한다.
- 불안을 자극하거나 합격·최신성·정확성을 근거 없이 보장하지 않는다.

검토 결과: `UX Writing: PASS` — 설계와 예시 문구에 정책을 적용했고 사실·조건·불확실성 보존을 발행 조건으로 포함했다. 실제 화면 렌더링과 사용자 테스트는 구현 전이므로 통과했다고 기록하지 않는다.

## 20. 구현 전 승인 조건

이 문서를 Owner가 승인한 뒤 별도 구현 계획을 작성한다. 구현 계획은 최소 다음 순서로 분리한다.

1. 데이터 모델과 migration
2. 브리핑 반입·파싱·멱등성
3. 후보 점수화·상태 전이·검수 명령
4. Admin 후보 작업함
5. Article Draft 연결과 publish guard
6. 재검수 큐와 측정
7. 파일럿 운영 및 프로덕션 반입

문서 승인 전에는 예약 작업 수정, migration, DB 반입, 자동 초안, 발행 또는 배포를 실행하지 않는다.
