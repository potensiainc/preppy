# 카드 전체 클릭 · 구현 및 검수

## 승인된 동작

| 대상 | 카드의 빈 공간·제목 클릭 | 카드 안의 별도 링크 |
| --- | --- | --- |
| 영어유치원·사립초 기관 카드 | 해당 기관 상세 | 모집 안내가 있으면 해당 안내로 이동 |
| 모집·입학정보 카드 | 해당 모집·입학정보 상세 | 기관명을 누르면 해당 기관 상세로 이동 |

홈에서 사용하는 공용 `InstitutionCard`, `OpportunityCard`에 적용했다. 같은 컴포넌트를 쓰는 다른 화면에도 같은 동작이 적용된다. 아티클 카드나 별도 영어유치원 전용 카드의 구조는 변경하지 않았다.

## 구현

- 기존 제목 링크의 가상 요소를 카드 전체에 펼친다. 카드에 클릭 핸들러나 중첩 링크를 추가하지 않는다.
- 별도 링크는 한 단계 위에 두어 원래 목적지로 이동한다.
- 제목 링크에 키보드 포커스가 오면 카드 전체에 테두리를 표시한다. 별도 링크의 기존 포커스 표시도 유지한다.
- 기존 AnalyticsLink를 유지한다. 이번 변경으로 새 추적 이벤트나 개인정보 수집을 추가하지 않았다. 정적 브라우저 테스트는 링크 동작을 확인하며 실제 분석 이벤트 전송을 검증한 것은 아니다.
- DB·API·기관 데이터·입학정보 텍스트·목적지 URL은 변경하지 않았다.

## 로컬 검증

- 실제 React 카드와 실제 운영 CSS를 로컬 전용 테스트 서버에서 렌더링했다. 운영 DB 사용이나 합성 데이터 반입 없음.
- 변경 전 320px에서 카드 하단의 빈 공간을 터치하면 목적지로 이동하지 않아 테스트가 실패하는 것을 확인했다.
- 변경 후 Chromium 320·390·1440px에서 네 사례(영유, 사립초, 입학정보, AnalyticsLink 사용 기관 카드) 모두 통과했다.
- 검증 항목: 빈 공간 클릭/터치, 네 모서리의 링크 영역, 별도 링크의 원래 목적지, Enter 이동, 전체 카드 포커스, 데스크톱 Ctrl+클릭 새 탭, 가로 넘침 없음, JavaScript 비활성 모바일 터치.
- 모바일 포커스 화면을 직접 열어 카드 전체 테두리와 정보 배치를 확인했다.
- 관련 단위 테스트 24개, TypeScript, 변경 파일 ESLint 통과.
- 초기 로컬 빌드는 시스템 가상 메모리 부족으로 실패했다. 설치된 Next.js의 작업 수 계산 방식을 확인하고, 이번 명령에만 `CIRCLE_NODE_TOTAL=2`를 설정해 한 작업자로 실행한 빌드는 통과했다. 제품 설정은 변경하지 않았다.
- 증거: `test-results/card-links-before`, `test-results/card-links-local/report.json`, `test-results/card-links-local/390-focus.png`.
- 재현: `npx tsx tests/browser/card-links-fixture.tsx` 실행 후 `python tests/browser/run-card-links.py --base-url http://127.0.0.1:3317 --fixture`.

## UX Writing: PASS — 구현·로컬 검수 범위

- `docs/PREPPY_UX_WRITING_POLICY.md` 전체를 적용했다.
- 사용자 노출 문구를 새로 만들거나 고치지 않았다. 기관명, 모집 제목, 학년도, 예정·마감 상태, 일정, 내용 확인 시각을 유지한다.
- 카드의 대표 제목이 링크의 접근성 이름으로 남아 실제 이동 목적지와 일치한다. 모든 텍스트를 한 개의 긴 링크 이름으로 합치지 않았다.
- 별도 모집 안내·기관명 링크를 제거하지 않아 기존 정보 접근 경로를 보존한다.
- 단위 검사와 실제 카드 이동으로 확인한 범위만 통과로 기록한다. Safari·실물 스마트폰·스크린리더 사용자 검사를 수행했다고 주장하지 않는다.
