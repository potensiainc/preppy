# 기관 유형별 모집·입학 일정

## 문제와 범위

`/curation/calendar`는 월별 달력이 아니라 홈 큐레이션의 현재 일정 최대12개를 보여주는 목록이다. 기존 카드는 일정 종류와 상태만 강조해 영어유치원·국제학교·사립초를 구별하기 어려웠다. `OpportunityCardDTO.institution.category`는 이미 canonical institution에서 전달된다.

이 변경은 이 목록에만 적용한다. 홈·설명회 목록·아티클·기관 상세의 공용 카드와 스타일은 수정하지 않는다. 전체213회 설명회나 전체 학교 일정으로 목록 범위를 확대하지 않는다. 데이터·DB migration·알림·로그인 변경은 없다.

## 동작

- 전체/영어유치원/국제학교/사립초 필터와 목록 기준 건수. 0건 필터도 선택할 수 있다.
- `?category=` URL 상태를 서버에서 검증한다. 새로고침·공유·브라우저 뒤로가기에 같은 선택을 사용할 수 있다. 잘못된 값/중복 배열 값은 전체로 돌아간다.
- 기관 유형은 이름·일정 종류로 추정하지 않는다. 인식되지 않은 값은 `기관 유형 미확인`으로 별도 표시한다.
- 카드의 텍스트 유형 배지와 ●/◆/■ 표식, 대비를 갖춘 색상·상단 경계를 함께 사용한다. 표식은 장식으로 접근성 트리에서 숨기고 유형 텍스트는 유지한다. 영어유치원 배지에는 `(학원)`을 함께 표시한다.
- 일정 종류, 기관 유형, 신청 상태를 각각 분리한다. 주요 일정은 날짜 단위로 표시한다. 현재 DTO가 원문의 명시적 시간과 자정 보정값을 구별하지 못하므로 ISO timestamp만으로 시간을 단정하지 않는다. 시간은 상세 안내에서 확인하도록 안내하며 학교 전체 이름·일정 제목은 보존한다.
- 실제 anchor 링크, 선택 상태 aria-current, 명확한 focus-visible, 모바일2열 필터/1열 카드. 긴 이름은 생략하지 않고 줄바꿈한다.
- 월 이동은 원래 없는 기능이므로 추가하지 않는다. 상세 복귀는 URL 필터와 브라우저 history로 유지한다.

## UX Writing 검토

정책: `PREPPY_UX_WRITING_POLICY.md` 전체 및 `CONTRIBUTING.md`를 적용했다.

- 대상: 이 페이지의 필터·결과 요약·카드 정보 순서·빈 결과.
- 새 문구: `어떤 기관의 일정을 찾으세요?`, `기관 유형을 선택해 일정을 나눠 보세요.`, `홈에 소개된 N개 일정 안에서 나눠 보여드려요. 전체 학교의 모든 일정은 아니에요.`, `신청 기간과 행사 날짜는 상세 안내에서 각각 확인해 주세요.`
- 빈 결과: `이 목록에는 [유형] 일정이 없어요`, `학교의 일정이 없다는 뜻은 아니에요. 다른 유형이나 학교·기관 안내를 살펴보세요.`
- 근거/조건: canonical category만 사용; 기존 일정·상태·확인일은 그대로 표시; 신청 가능 여부를 새로 단정하지 않음. 홈 범위의0건을 학교 전체 일정 부재로 표현하지 않음.
- 코드/SSR 검토: 텍스트 배지·접근성 이름·0건/전체빈값·잘못된 필터·긴 학교명 보존·날짜 정밀도·기존 홈/briefings/guides 회귀 검증.
- **UX Writing: PASS.** 사용자가 2026-10-19 15:26UTC에 지정한 현재 Chrome1에서 실제375/390/412px·데스크톱1440px를 확인했다. 텍스트 유형 배지,0건 안내,키보드Tab/Enter와 가시적 초점,필터URL,상세 진입 후 뒤로가기와 새로고침의 선택 유지,긴 제목2줄 전체 표시를 검증했다. 모든 폭에서 가로넘침과 카드/제목 잘림이 없었다. 증거는 `docs/qa/calendar-institution-types/`에 있다. 최초UI3cc307f와 정렬수정c94b9b6의 UI파일은 동일하다. 최종 배포이미지는 staging에서 다시 확인한 뒤 production에 적용한다.

## QA와 배포 조건

최종 단위1656개, 로컬 격리 PostgreSQL 통합10개를 검증한다. TypeScript·변경 파일lint·prebuild도 검증한다. 필수 배포 전 `npm run deploy:preflight`, 최신main 포함, 필수 CI, 단일 불변 이미지의 staging 검증 후 production 순서를 지킨다. 세 운영 플래그는 false로 유지한다.

지정 환경: DESKTOP-LLAQ2GV의 사용자가 현재 연결로 명시한 Chrome1을 사용했다. 초기에는 프로필 미식별/30초 timeout으로 막혔지만 사용자 확인 후 기존 연결에서 QA를 완료했다. 다른 브라우저/프로필로 전환하거나 계정에 새로 로그인하지 않았다. 최종배포 결과는 별도 release evidence에 기록한다.

## 직접 관련된 정렬 리뷰 수정

영어유치원 설명회의 표시 날짜는 행사 시작일인데 SQL 정렬 키가 신청일 우선인 불일치를 로컬 DB 회귀 테스트로 재현했다. 해당 category/kind만 행사 시작일로 정렬 키를 맞춘다. 홈의 대표 회차 선택과 설명회 목록의 같은 상태 내 순서에 적용되며, 기존 상태 우선순위와 다른 기관 유형의 신청 마감일 기준은 유지한다. 이 읽기 모델 변경에는 DB/data migration이 없다.

최초 UI 이미지3cc307f는 staging 배포8aedb86f-f865-4c76-9c52-e67ec7001a16에서 HTTP 필터/0건/다른큐레이션 분리 검증을 통과했다. 홈 제목·헤더 링크와 기존CSS규칙214개는 그대로이며 신규달력 전용 규칙56개가 추가돼 CSS번들명만 바뀌었다. 이는 실제 viewport QA나 이후 정렬 수정의 이미지 검증을 대체하지 않는다.

## 출시 전 날짜 정밀도 리뷰

`extractLiveAdmissionProposal`가 날짜만 있는 원문을 KST자정의 ISO값으로 정규화하고 공개카드DTO에서 explicitTime정보가 사라지는 경로를 확인했다. 원문11월6일이 ISO11월5일15:00Z가 되는 실제 extractor fixture를 카드까지 통과시켜 날짜만11월6일로 표시하고 `00:00`을 만들지 않는 회귀 테스트를 추가했다. DTO/DB/data를 확장하지 않고 기존 날짜표시로 보수적으로 처리한다. 전체목록 자체가 빈 경우 같은페이지를 새로 여는 `전체 일정 보기` 링크도 숨긴다. 이 최소표시수정은 최종이미지의 실제Chrome staging QA에서 다시 확인해야 하며, 위 스크린샷은 초기UI검증 기록이다.
