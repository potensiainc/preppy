# 기관 유형별 모집·입학 일정

## 문제와 범위

`/curation/calendar`는 월별 달력이 아니라 홈 큐레이션의 현재 일정 최대12개를 보여주는 목록이다. 기존 카드는 일정 종류와 상태만 강조해 영어유치원·국제학교·사립초를 구별하기 어려웠다. `OpportunityCardDTO.institution.category`는 이미 canonical institution에서 전달된다.

이 변경은 이 목록에만 적용한다. 홈·설명회 목록·아티클·기관 상세의 공용 카드와 스타일은 수정하지 않는다. 전체213회 설명회나 전체 학교 일정으로 목록 범위를 확대하지 않는다. 데이터·DB migration·알림·로그인 변경은 없다.

## 동작

- 전체/영어유치원/국제학교/사립초 필터와 목록 기준 건수. 0건 필터도 선택할 수 있다.
- `?category=` URL 상태를 서버에서 검증한다. 새로고침·공유·브라우저 뒤로가기에 같은 선택을 사용할 수 있다. 잘못된 값/중복 배열 값은 전체로 돌아간다.
- 기관 유형은 이름·일정 종류로 추정하지 않는다. 인식되지 않은 값은 `기관 유형 미확인`으로 별도 표시한다.
- 카드의 텍스트 유형 배지와 ●/◆/■ 표식, 대비를 갖춘 색상·상단 경계를 함께 사용한다. 표식은 장식으로 접근성 트리에서 숨기고 유형 텍스트는 유지한다. 영어유치원 배지에는 `(학원)`을 함께 표시한다.
- 일정 종류, 기관 유형, 신청 상태를 각각 분리한다. 주요 일정의 날짜·확인된 시간 정밀도, 학교 전체 이름, 일정 제목을 보존한다. 날짜만 있으면 임의의 시간을 추가하지 않는다.
- 실제 anchor 링크, 선택 상태 aria-current, 명확한 focus-visible, 모바일2열 필터/1열 카드. 긴 이름은 생략하지 않고 줄바꿈한다.
- 월 이동은 원래 없는 기능이므로 추가하지 않는다. 상세 복귀는 URL 필터와 브라우저 history로 유지한다.

## UX Writing 검토

정책: `PREPPY_UX_WRITING_POLICY.md` 전체 및 `CONTRIBUTING.md`를 적용했다.

- 대상: 이 페이지의 필터·결과 요약·카드 정보 순서·빈 결과.
- 새 문구: `어떤 기관의 일정을 찾으세요?`, `기관 유형을 선택해 일정을 나눠 보세요.`, `홈에 소개된 N개 일정 안에서 나눠 보여드려요. 전체 학교의 모든 일정은 아니에요.`, `신청 기간과 행사 날짜는 상세 안내에서 각각 확인해 주세요.`
- 빈 결과: `이 목록에는 [유형] 일정이 없어요`, `학교의 일정이 없다는 뜻은 아니에요. 다른 유형이나 학교·기관 안내를 살펴보세요.`
- 근거/조건: canonical category만 사용; 기존 일정·상태·확인일은 그대로 표시; 신청 가능 여부를 새로 단정하지 않음. 홈 범위의0건을 학교 전체 일정 부재로 표현하지 않음.
- 코드/SSR 검토: 텍스트 배지·접근성 이름·0건/전체빈값·잘못된 필터·긴 학교명 보존·날짜 정밀도·기존 홈/briefings/guides 회귀 검증.
- **UX Writing: FIX_REQUIRED (실제 지정 Chrome에서375/390/412px·데스크톱 줄바꿈/초점/상세 복귀 QA 미완료).** 코드/문구 사전 검토 통과를 실제 화면 QA 완료로 대체하지 않는다. 화면 QA 후 결과를 갱신해야 한다.

## QA와 배포 조건

최종 단위1655개, 로컬 격리 PostgreSQL 통합8개 통과. TypeScript·변경 파일lint·prebuild도 검증한다. 필수 배포 전 `npm run deploy:preflight`, 최신main 포함, 필수 CI, 단일 불변 이미지의 staging 검증 후 production 순서를 지킨다. 세 운영 플래그는 false로 유지한다.

지정 환경: DESKTOP-LLAQ2GV Chrome `포텐시아 주식회사` 프로필만 사용한다. 현재 inventory에서 프로필이 식별되지 않았고 후속 CUA 재조회가30초 timeout으로 실패했다. 다른 브라우저/계정으로 대체하지 않는다. 실제 viewport와 키보드/상세 복귀 QA가 끝나기 전 production 완료로 보고하지 않는다.
